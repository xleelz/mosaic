## 2. Wrong claims in the model

1. `sampling-params.post-init` cites `sampling_params.py:449-555` and `567-592`, but it omits `__post_init__`'s first step (`557-565`): a temperature in (0, 0.01) is raised to 0.01.
2. `openai-serving-chat.validate-request` drops the result of `check-tool-usage`. The defaulted `tool_choice: "auto"` (`protocol.py:951-954`) never reaches `online-renderer.render-chat`, so `tools` without `tool_choice` generates instead of returning a 400 (`online_renderer.py:258-264`).
3. Streamed validation errors (`openai-serving-chat.chat-completion-stream-generator`): the model sends the assistant role chunk, then `{"error": {"code": 500, "type": "InternalServerError"}}`. In the code, the error comes before any chunk (`chat_completion/serving.py:527-537`) and maps a `VLLMValidationError` to 400 `BadRequestError` (`error_response.py:41-44`, `generate/base/serving.py:183-197`).
4. `hf-renderer.render-messages` refuses media on a text-only model with `Multi-modal processor not available for text-only models` (`renderers/base.py:228-230`). The code fails earlier, while the item is tracked: `llama-8b is not a multimodal model` (`chat_utils.py:648-650,705-720`, `multimodal/registry.py:157-159`).
5. `base-renderer.tokenize-prompt` applies `_token_len_check` against `max-model-len` for /tokenize. The code builds /tokenize's TokenizeParams with `max_total_tokens=None` (`tokenize/protocol.py:38-43`), so it doesn't check.
6. `online-renderer.render-chat`: the named-`tool_choice` message is built with `string(map)`, which aborts the run. The code uses `function "<name>"` (`online_renderer.py:271-280`).
7. `online-renderer.render-completion`: a `list[int]` prompt (one token-id prompt, `completion/protocol.py:52-58`) is iterated as a list of text prompts.
8. `sampling-params.verify` cites `sampling_params.py:901-917` but implements only `_validate_logprobs` and structured outputs. It has none of `_validate_logit_bias`, `_validate_stop_token_ids` or `_validate_allowed_token_ids`.
9. `openai-serving-completion.create-completion`: `use_beam_search` reuses the sampling path with `n` as the number of samples. The code runs `OnlineBeamSearch` in the API process (`generate/beam_search/online.py:40-226`).
10. `base-processing-info.validate-num-items` and `parse-mm-data` are correct on their own (`context.py:607-660`), but serving never calls them.

## 4. Simulator gaps

- **Python float repr** (S3-1): CEL `string(0.0)` yields `"0"`, so messages built from pydantic-coerced floats (`got 0.0.`) can't be reproduced exactly. The scenarios assert only the prefix.
- Nothing else in this group needed a feature mosaic lacks. The S3-5 hang with two prompts × n=2 ("3 tasks were still waiting") looks like a model defect in the parallel-sampling fan-out, not a simulator limit, because one prompt with n=2 and two prompts with n=1 both run. Response headers (S3-7 c) are expressible (`return … headers`), but the world has no knob for them.

## Fix requests

### serving-api
1. **Prompt normalization**: model `prompt_to_seq` in `llm.add-completion-requests` (offline.py:317). A bare string, dict or non-empty int list is one prompt, and a list is a sequence. Render each element with `parse_dec_only_prompt` (preprocess.py:129-155): a list of ints is a `TokensPrompt`, and other types raise `TypeError`. Widen the `llm.generate` / `llm.enqueue` / `llm.add-completion-requests` prompt schemas to allow token lists. An empty token prompt should then fail in the input processor ("The decoder prompt cannot be empty", input_processor.py:566).
2. **Cohere route errors**: send `post-cohere-v2-chat` (and `-render`) exceptions and `ErrorResponse`s through `cohere-serving-chat-v2.error-response` (api_router.py:143-150, 190-195). Then the body is `{message}` plus `id` only when an X-Request-Id or request metadata is present.
3. **DeepSeekV3ReasoningParser**: add the per-request delegation, R1 (`<think>`/`</think>`, all reasoning when `</think>` is missing) when `thinking`/`enable_thinking`, else identity (all content, no reasoning). Add `chat_template_kwargs` to `ServingChatCompletionRequest`, and pass it into the parser (`_make_parser(request, tokenizer, _effective_chat_template_kwargs(request))`, serving.py:975-978). Keep `content` null rather than `""` when the parser returns None.

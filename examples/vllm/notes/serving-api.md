## 6. Assumptions

- Tokenization is approximated: one token per whitespace word, plus Llama-3.1 special tokens and the
  assistant generation prompt (the real template also injects a "Cutting Knowledge Date" system block).
  The 14-token chat prompt in scenarios comes from this rule.
- The streaming generator emits one delta per word of the final text, not per engine step.
- Error `code` for routes is the ErrorInfo.type the code really returns (`BadRequestError`,
  `NotFoundError`, `InternalServerError`, `invalid_request_error`, `Not Found`, `Bad Request`,
  `Service Unavailable`, `PermissionDeniedError`, ...) with the HTTP status; internal exceptions use
  kebab-case class names with status 0 (engine-dead-error keeps 500 per the fixed table).
- Responses ids are `resp_<n>` from a counter (code: `resp_<uuid4>`).
- Query parameters are an extra `query` field next to {path, body, headers}.
- The RL "abort everything" case passes an empty id list (the tracked ids live in engine-core).
- The offline step loop stops when has_unfinished_requests is false or every added request has a
  finished output (equivalent under FINAL_ONLY, common/offline.py:574-578).

## 7. Docs / common knowledge vs code

- The brief's error table names `invalid_request_error` for 400 and a file
  `vllm/entrypoints/openai/protocol.py` that no longer exists; the code's default type is
  `BadRequestError` (serve/exception_handling/error_response.py:14-19); only the Responses API and the
  renderer use `invalid_request_error`.
- The Responses store is off by default (VLLM_ENABLE_RESPONSES_API_STORE=0): store=true is silently
  dropped and background requests are refused with 400 -- unlike OpenAI's default.
- A background response whose generation raises (not a cancellation) is NOT marked failed: the
  exception escapes the task and the stored status stays `queued` (responses/serving.py:1087-1102).
- Pooling and speech routes are not registered for generate models (404), not 501.
- Scale-out routes are registered as 403 handlers unless enabled (scale_out/factories.py:84-110).

## 8. Simulator gaps

- Per-step streaming: AsyncLLM.generate is one call returning the final output; chunks are derived
  afterwards (chat_completion/serving.py:526-760).
- Cancellation: with_cancellation is modeled by a token on the handler call; the canceled callee keeps
  running late, while in vLLM the CancelledError aborts the engine request inside AsyncLLM.generate
  (async_llm.py:779). The abort itself is engine-core's.
- terminate_if_errored reads `engine.errored and not is_running`; a stub cannot return a dead state,
  so scenarios fault `async-llm.errored` and the behavior treats a failed read as errored.
- Regex-driven parsers: DSML parsing uses CEL `replace`/`matches` and `eval` as a JSON decoder
  (JSON literals happen to be valid CEL); GLM reasoning end is a last-occurrence comparison on text.

- **Defaulted tool_choice**: `validate-request` now returns the rewritten body, so tools without tool_choice reach the renderer as `auto` and get a 400. The named-choice message is `function "<name>"`. Tools are passed to the chat template, and `--exclude-tools-when-tool-choice-none` is modeled.
- **Streamed errors**: the role chunk is sent only after the first RequestOutput. An exception goes through `create_error_response` (a VLLMValidationError is 400 BadRequestError with its param) as the first frame, followed by [DONE].
- **/tokenize**: TokenizeParams `max_total_tokens=None`, so there is no length check. It honors add_generation_prompt, continue_final_message (and refuses both together), add_special_tokens and tools. /detokenize refuses a negative id in pydantic (`Bad Request`, param `body.tokens.<i>`).

A token-id prompt now becomes one TokensPrompt through `prompt_to_seq` and `parse_dec_only_prompt`. Echo prepends the prompt text. The request id falls back to the body's request_id.
- **Online beam search**: `generate-base-serving.beam-search` (online.py) sends one max_tokens=1 request per beam per step, named `<id>-<uuid>-beam-<i>`, with logprobs 2·beam_width. The bare request id is used. **Cross-area:** engine-core's RequestOutput completions carry no `logprobs`, so beams never extend (S3-6-ab).
- **Multimodal tracker**: `hf-renderer.render-messages` now tracks part by part. `image_embeds` needs --enable-mm-embeds. A text-only model raises `<served name> is not a multimodal model`. Every item calls models-layers' `base-processing-info.validate-num-items`. **Cross-area (models-layers):** that interface appends the `--limit-mm-per-prompt` hint when the supported limit is None (context.py:612-626 does not), and it drops `parameter=<modality>`. S3-4-a fails on both.

- **`validate_json_request`**: a non-JSON Content-Type is a 400 on every POST route. ASSUMPTION: a missing header means a JSON client.

## 6. Assumptions where the code did not settle it

- Worker state keeps only what the worker owns:
  - request slots (`slot`, `prefill_len`, `prompt_len`);
  - per-slot sampling and bad-word params;
  - the pending `execute_model_state`;
  - drafts.

  It does not mirror num_computed_tokens or output tokens across steps (the real
  `RequestState` does; see gaps). num_computed_tokens come from each SchedulerOutput.
- Sampled token ids are seeded random placeholders (`random(128000)+100`). Draft acceptance is a
  choice (`rejection-sampler.sample.acceptance`); an n-gram match is a choice.
- Batch order follows `sort_batch_req_ids`: drafts first, then decode-length requests, then by
  token count.
- The V1 path takes a non-schema `hybrid` flag in its SchedulerOutput input, standing in for a
  hybrid model config.
- PP (pipeline parallel) send/recv in `execute_model` is not modeled: PP size is 1 in every
  fixture.

## 7. Docs vs code

- Common knowledge says "vLLM uses 90% of GPU memory". The code default is **0.92**
  (cache.py:102).
- The V1 runner is widely described as the GPU runner. In 0.32 the **V2 runner**
  (`v1/worker/gpu/model_runner.py`) is the default whenever no unsupported feature is configured.
- `execute_model` returning the output is the old contract. In V2 it returns None, and
  `sample_tokens` produces the output.

## 8. Simulator gaps

- No int/float split in config: integer configs must be wrapped in `int(...)` in CEL.
- Kernel GPU time on a FULL graph replay has to sit on `cuda-graph-manager.run-fullgraph`'s
  latency, because the model's forward is not called in Python there. The formula duplicates the
  forward stub's.
- Per-row token values and probabilities can't be computed, so bad-word masking is returned as
  data (`masked`) rather than changing the sampled token.

## Fix round (FIXES.md)

- **V6, deterministic greedy.**
  - `sampler.sample` gives greedy rows (temperature 0: plain argmax in the Gumbel kernel,
    gumbel.py:21-44) and seeded rows a deterministic token: (prompt hash × 31 + position × 7919
    [+ seed]) mod 128000 + 100.
  - The prompt hash is recorded per slot at `add-requests`. Unseeded random rows stay `random()`.
  - Scenario: `wr-greedy-is-deterministic`.
- **Non-last PP ranks** (model_runner.py:2108-2127): `sample-tokens` does not sample. It calls
  `pp-handler.receive`, advances num_computed_tokens, resets Mamba state with 0 sampled when the
  next step is not all decode, and returns a KV-only output.
- **PPHandler** (pp_utils.py) is a new component:
  - the receive ring is pre-seeded with pp_size empty slots;
  - the last rank `broadcast`s on channel `pp-sampled`;

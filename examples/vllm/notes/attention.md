Boundary components (`cuda-platform`, `custom-ops`, `group-coordinator`) carry no parent, so they
merge with the owners' definitions without warnings. KV block tables are the scheduler-kv datum. I take
them only as `block_table` (lists of `block_ids`) and `slot_mapping` inputs, the way the SchedulerOutput
→ CommonAttentionMetadata path delivers them. I never store them. No scheduler-kv interface is called.

Callers in other fragments: models-layers calls `flash-attention-impl.forward` and
`.do-kv-cache-update` with only `{num_tokens, num_heads, num_kv_heads, head_size}`. Both behaviors first
`merge` the request defaults (a one-request decode step with FA3) over the input, so such calls run.
In the merged model, all 115 attention scenarios pass.

forward cost, but it means attention shows no time of its own.

## 6. Not settled by the code / assumptions

- The device capability (SM90, H100-class) is assumed, so FA3 is the default version.
- The platform's priority loop (`CudaPlatform.get_valid_backends`) belongs to config-platform. Its
  stub returns FlashAttentionBackend, and `validate_configuration` is modeled as its own flow.
- `validate_configuration` models only FLASH_ATTN and TRITON_ATTN rows. Both support sliding window
  and batch invariance, so those checks are omitted. The FP8-KV rule is simplified: FA3+SM90 or
  FA4+SM100 (the FA4 head-512 SM90 case is ignored).
- In the FA builder, the DCP decode/prefill split uses query_len ≤ 1 as decode. Interleave size I=1.
- Triton reshape-and-cache: the SM89 FP8 check is approximated with the major version only.
- CPU MLA: `latent_rows` in `cpu-mla-impl` state represents the tensor contents the impl writes, not
  block bookkeeping (which stays with scheduler-kv).
- MLA prefill override dispatch (Python virtual methods) is modeled as an `if` on the backend name.

## 7. Docs / common knowledge vs code

- Many expect FlashAttention to be the backend everywhere. On SM100 the priority is FLASHINFER first
  (`platforms/cuda.py`), and FA4 replaces FA3 on Blackwell.
- `dcp_comm_backend` defaults to None in code, and VllmConfig fills `ag_rs`.
- The Triton 3D (segmented-softmax) path is used only for pure-decode batches up to
  `128 // num_kv_heads` sequences (16 for Llama-8B), snapped to a CUDA-graph capture size.

## 8. Simulator gaps

- Kernel latencies are integer ms: sub-ms per-layer attention rounds to 0 (any kernel interface).
- Explicit `null` in scenario/step input overrides is dropped by the deep merge, so "attn_metadata is
  None" is modeled with a `profiling_run` flag (flash_attn.py:1221).
- `fill: true` replaces explicit nulls with fake data, so calls to `cuda-platform.get-attn-backend-cls`
  are not filled.
- A stub's response can't be steered without mocks, so `selector.get-attn-backend`'s "platform
  returned an empty class path" branch (selector.py:220-223) is never run. It is the one unexecuted
  `fail` (behavior coverage 515/516).
- `dist.all_to_all_single` in `dcp_a2a_lse_reduce` (dcp.py) is torch.distributed, not a
  GroupCoordinator method, so it's narrated rather than modeled as a parallel join.

## 9. Known gaps

## Reconciliation round

- `flash-attention-metadata-builder.build` (decision 2): the request now requires only `common`
  (CommonAttentionMetadata). Within it, these are required because the dataclass has no default:
  num_reqs, num_actual_tokens, max_query_len, max_seq_len, query_lens (query_start_loc), seq_lens,
  block_table, slot_mapping. Everything else takes the code's default, merged in by the behavior's
  first step:
  - causal = True; `seq_lens_cpu_upper_bound` = None, which was wrongly `True` before and is now fixed;
  - fast_build = False;
  - the builder state from VllmConfig: FA3 on SM90, full CUDA graphs, max capture size 512,
    DCP from `decode-context-parallel-size`.
  A call without `common` fails with type-error, as Python's build() would. With no upper bound,
  DCP splits every request as an extend (split_dcp_context_queries); new scenario
  `attention-flash-build-metadata-dcp-no-cpu-bound`.
- Configs (decision 7): attention owns kv-cache-dtype, decode-context-parallel-size and dcp-comm-backend.
- Latency (decision 9): kernel `latency_ms` is now fractional (µs precision, per layer). The `int()`
  truncation is gone.
- Seed (decision 10): fixture `attention-seed` holds the plain-key initial state of `selector`,
  `attention-backend` and `cpu-mla-impl`. Every attention scenario lists it.

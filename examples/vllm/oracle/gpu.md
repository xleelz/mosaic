## Fix requests

### scheduler-kv: the scheduler never drives the KV connector

Exposed by `test_nixl_connector.py:254` (`oracle-distributed-nixl-basic-interface`).

- `scheduler.add-request` / `SchedKvRequest`: carry `kv_transfer_params` into the request table (`vllm/v1/request.py`).
- `scheduler.schedule`, waiting loop: when `config['kv-connector'] != ''`, call `kv-connector-base-v1.get-num-new-matched-tokens` with the block-aligned local hit (`vllm/v1/core/sched/scheduler.py:970-990`). Allocate for local plus external tokens, then call `kv-connector-base-v1.update-state-after-alloc` with the request's blocks (`:1285-1293`). When `load_kv_async`, set status `WAITING_FOR_REMOTE_KVS` and do not schedule the request (`:1320-1330`). Resume it once the connector reports the receive finished (`:2440-2447`).
- `scheduler.schedule`, output: call `kv-connector-base-v1.build-connector-meta` and attach the result as `kv_connector_metadata` on `SchedulerOutput` (`:1526-1530`).

### distributed: connector metadata and MoRIIO scheduler hooks

Exposed by `test_nixl_connector.py:254` and `test_moriio_hma_scheduler.py:170`.

- `moriio-connector-scheduler`: add `update-state-after-alloc` and `build-connector-meta` (`moriio_connector.py:917`, `:1242`), including the hybrid split `split_block_groups` (`:1353-1375`: the attention group's blocks plus one running-state list per Mamba group). Add `MoRIIOConnector` to `kv-connector-base-v1.update-state-after-alloc`'s dispatch map.

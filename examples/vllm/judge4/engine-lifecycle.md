## 2. Wrong claims in the model

1. **TTFT/e2e anchor.** `output-processor.add-request` sets `arrival_ms: now` after rendering and tokenization. The code stamps `arrival_time` before the chat template (`renderers/base.py:1296,1336`), so every modeled TTFT and e2e is short by the render time. `input-processor.process-inputs` also returns `arrival_time: = now`.
2. **ITL source.** `output-processor.process-outputs` computes ITL as API-side `now - last_token_ms`. The code uses consecutive `EngineCoreOutputs.timestamp` values from the engine core (`stats.py:548-554`). Its cite to `stats.py:505-557` doesn't support the clock it uses.
3. **`stat-logger-manager.record-prometheus` / `init-prometheus`** cite `loggers.py:1138-1330` but model only the e2e, TTFT, ITL, prompt-token and generation-token histograms, as `{count, sum}` without buckets. Ten request histograms are absent (queue, prefill, decode, inference, TPOT, params_n, params_max_tokens, max_num_generation_tokens, prefill_kv_computed, num_preemptions). `buckets.histogram-buckets` is correct but never wired.
4. **`stat-logger-manager.init`** summary says "LoggingStatLogger for a single API server", but the `client_count > 1` branch and its warning (`loggers.py:1383-1389`) aren't modeled. The logger is always added.
5. **`server-info-router.get-server-info`** accepts any `config_format` and returns the text config. The code's `Literal["text","json"]` gives 400 for anything else. Its title "Env vars whose name contains KEY are left out" is not implemented: `vllm_env` is a constant.
6. **`multi-modal-cache-factories.processor-cache-from-config`** fails with `Unknown cache type: shm`. The code returns `ShmObjectStoreSenderCache` (`factories.py:62-63`), so a valid shm deployment fails in the model.
7. **`async-mp-client.init`** says "READY carries num_gpu_blocks". In the code, `num_gpu_blocks` arrives in the `EngineCoreReadyResponse` on the input socket (`core.py:1781-1803,1871-1875`). The handshake READY carries only status, local, headless and (under DP) `parallel_config_hash` (`core.py:1330-1343`).
8. **`model-config.post-init` / `engine-args.create-model-config`** drop `dtype`, `mm_processor_cache_type` and `mm_shm_cache_max_object_size_mb`, so the validations in `vllm-config.get-quantization-config` and `multimodal-config.init` can't be reached from `vllm serve`.

Entry-point coverage in the group: `/load`, `/health`, `/ping`, `/version`, the FP8 checks and the custom-bucket validators are modeled by entities that implement them. `run_multi_api_server`, `FlexibleArgumentParser.parse_args` (the serve arg rewrites), the engine handshake (`startup_handshake` / `wait_for_engine_startup` states), the `VLLM_ENGINE_READY_TIMEOUT_S` wait and `ModelConfig.supports_multimodal_inputs` are not. They have no entity, or only an entity that cites the lines without modeling them (`core-engine-proc-manager.launch` cites `utils.py:1361-1400` but is a direct call).

Citation sample (`--cite-sample 12 --seed 4417`): 12 of 12 resolve and support their claim. Two are weak: `ec-consumer-control-server.loop` "return" cites a loop line, and `weight-transfer-engine.start-weight-update` cites a whole file. Beyond the sample, I read 15 behaviors in this group next to their cited code; the wrong ones are listed above.

## 4. Simulator and world gaps

- **A config can't be unset.** `config: {served-model-name: null}` drops the key, and the model's `config['served-model-name']` then aborts. `{$null: true}` isn't interpreted in `config`. So "no `--served-model-name`" can't be expressed on a world that pins it (L4-5 c). This is a simulator or world gap, not a model one.
- **World:** no Qwen3-30B-A3B checkpoint, and no `api-server-count` or `VLLM_ENGINE_READY_TIMEOUT_S` config knob (L4-7, L4-8 b, L4-3 d).
- No step was scored sim-gap. Everything not passed is missing or partial modeling: histogram buckets, multi-process API servers and the handshake messages can all be expressed in mosaic.

## 2. Wrong claims in the model

1. **`ext-host-save-participant.participate`**: the summary says "Fires onWillSaveTextDocument in the extension host (1750 ms budget)". No budget is modeled: it is a stub, and its caller `text-file-save-participant.participate` has no `timeout_ms`. A hung extension host delays the save by 30 s instead of 1.75 s (mainThreadSaveParticipant.ts:35-38).
2. **`text-file-models.save` and `on-model-content-changed`**: on save, `saved_version_id` is set to the file model's `version_id` (the "Save success clears dirty…" step, which cites textFileEditorModel.ts:1049-1068). The code remembers `textEditorModel.getAlternativeVersionId()` (textFileEditorModel.ts:1100-1108), and the undo-to-saved check compares against that. Result: after any undo or redo before a save, undo or redo back to the saved text leaves the model dirty (E7b).
3. **`text-model.undo`/`redo`**: these call `undo-redo-service.undo` and then `edit-stack.undo` directly. The service never holds the editor's elements (state `stacks: {}`), so the service hop is a no-op and the stated delegation ("TextModel.undo delegates to IUndoRedoService.undo(uri)") doesn't drive anything (textModel.ts:1604-1606).
4. **`text-file-models.resolve`/`revert` against the editor's `text-model`**: the code has one TextModel per resource, shared by `TextFileEditorModel.textEditorModel` and the editor. The model holds two independent copies, and file-side reloads (revert, external change, and resolve in general) never update the editor copy (E8, E9).
5. **`file-commands.cmd-workbench-action-files-save` (and `…-files-revert`)**: these require `input.resource`. The code resolves the command args, then the open-editors selection, then the active editor of the active group (fileCommands.ts:417-436, 577-584). Through the keybinding the model aborts (E1).
6. **`text-file-save-participant` state** lists 2 participants. The code registers 6 text-file participants: TrimWhitespace, CodeActionOnSave, FormatOnSave, FinalNewLine and TrimFinalNewLines (saveParticipants.ts:456-460), plus the extension host one (mainThreadSaveParticipant.ts:62). Separate flows exist for trim-whitespace, final-newline and code-actions, but nothing in the save chain calls them.
7. Minor: the edit stack's undo doesn't restore the cursor (`beforeCursorState`, editStack.ts:26-45), so the next typed character lands at the old cursor position (`impxort`).

Covered entry points checked:
- `workbench.action.files.save` (Ctrl+S), `workbench.action.files.revert`, `type` and `undo` are modeled by behaviors that do the work.
- The file-change entry is modeled at the listener (`text-file-models.on-did-files-change`), not at the watcher or file service. `universal-watcher` and `workspace-watcher` have only constructors.

## 3. Builder "docs versus code" findings (this group)

- files: "files.autoSave defaults to afterDelay on web and in the agents window; off on desktop" is **confirmed** (files.contribution.ts:270, 273).
- files: "Auto save never saves a model in conflict or error state" is **confirmed** (textFileEditorModel.ts:842-849). It covers AUTO, FOCUS_CHANGE and WINDOW_CHANGE.
- editor: "Format on save skips auto save" is **confirmed** (saveParticipants.ts:230-232; the model cites 231-233). It applies only to `SaveReason.AUTO` (after delay), not to focus or window change.
- platform-core: "An mtime mismatch alone is not a conflict; the etag must differ, and identical bytes are allowed" is **confirmed** (fileService.ts:519-537).
- New finding from this judge: `files.participants.timeout` doesn't apply to save participants (E2, E3). It covers file operation participants (create, rename, delete) only.

## 4. Simulator gaps

| Gap | Exposed by |
|---|---|
| A scenario step can't start while an earlier step's timers are pending, because steps drain their emits and timers before the next `at_ms`. So user input can't interleave with a debounce or delay timer. Needed: steps that fire at an absolute `at_ms` without waiting for earlier timers, or input events injected into one run. | E5 (`bench-e5-auto-save-debounce`) |
| A failed `call.end` trace event has no `ok` key (it is omitted when false), so `!e.ok` in expectations raises "no such key". Workaround: `has(e.error)`. `set` events don't expose `path` to CEL either. | E4 (while writing assertions) |

The missing 1750 ms budget, the missing Skip progress (E3) and the duplicated buffers (E7–E9) are model or contract issues. The simulator can express all of them: `timeout_ms`, choices, and a call or publish from `text-file-models.resolve` to the editor's text model.

## Fix requests

### main-process

1. **Agents window open intent.** Add `windows-main-service.open-agents-window` (`windowsMainService.ts:296-306`): open or reuse the Agents window, then apply `sendAgentsWindowOpenIntent` (`agentsWindow.ts:15-28`): skip when the window already existed, context is API and `reveal` is undefined; otherwise send `vscode:selectAgentsFolder` to the window when ready with folder, reveal (`'new'` or URI), source (default CommandLine when `cli.agents`, else Unknown), folderUriIsDefault, draft (only for `reveal == 'new'` or LINK context) and onboarding session. Make `native-host-main-service.open-agents-window` call it and force-focus the first window. Also model `resolveAgentsWindowFolder` (`agentsWindow.ts:30-37`).
2. **Onboarding tryout handoff.** Add `OnboardingTryoutHandoff` (`onboardingTryoutHandoff.ts:25-118`) behind the `onboardingTryout` channel: `open` validates the request, supersedes earlier pending requests, calls `windows-main-service.open-agents-window` with `{context: API, contextWindowId}`, requires exactly one window, focuses it, sends `vscode:runOnboardingTryout`, and waits up to 30 s for `complete` from that window (else cancels); `cancel` only from the source window; dispose cancels all pending with `vscode:cancelOnboardingTryout`.
3. **Snap environment.** Add `EnvironmentMainService.unsetSnapExportedVariables` / `restoreSnapExportedVariables` (`environmentMainService.ts:75-108`, Linux only) over a process-env state, and call them around pty host start (`electronPtyHostStarter.ts:87,105`).

### workbench-shell

1. **Account policy.** Add `AccountPolicyService` (`accountPolicyService.ts:84`): policy values computed from each policy definition's `value(policyData)` over the default account's policy data and managed settings, with value sources (Account, ServerManagedSettings), feeding `configuration-service`'s policy layer instead of seeded `state.policy`.
2. **Configuration resolver.** Give `configuration-resolver-service` a `resolve-async` interface (`variableResolver.ts:83`) that substitutes `${workspaceFolder}`, `${workspaceFolder:name}`, `${env:...}`, `${config:...}`, `${command:...}` from workspace-context, configuration and command state, and applies the platform-specific sub-object (`windows`/`osx`/`linux`).

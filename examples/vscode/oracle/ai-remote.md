## Fix requests

### agents
1. Model startup performance. Give `agent-host-startup-performance` a `mark` interface and a `marks` state. Call it from `agents-agent-host-startup` (bootstrapStart, configuration, telemetry, services, bootstrap; processStart is pre-seeded). Add `agent-service.mark-startup-complete(outcome)`, which marks hostReady and then startupSettled once the first listing has been served. Make `agent-service.list-sessions` mark sessionListStart/sessionList(outcome) and firstSessionList. Sources: agentHostBootstrap.ts:111-236, agentService.ts:1550-1562 and :5007, agentHostStartupPerformance.ts:83-108.
2. Make `sessions-chat-pet-achievement-contribution.start` call `chat-pet-service.unlock-achievement(agentsWindowOpened)` and subscribe to `sessions-management-service.on-did-send-request`. The send-request path should publish that event, and the handler should unlock firstChatMessage, plus imageRequest when `attached_context` has an image (src/vs/sessions/contrib/chat/browser/chatPetAchievements.ts:16-28).
3. Add the Agents-window `TitlebarPart` height: 44px by default and 35px when `window.density.layout` is compact (min == max). It should re-fire on a config change (src/vs/sessions/browser/parts/titlebarPart.ts:39,58-70,126).
4. Add the agent-host sandbox toggle policy: get-toggle-state and get-collapsed-state over session/confirmed/global/managed/allowsBypass/applyFailed (src/vs/platform/agentHost/browser/agentHostSandboxToggle.ts:40-57).
5. (Coordinator) Add `agents-seed` to the `full-*` worlds in worlds.yaml.

### chat
1. Add `chat-pet-service.unlock-achievement` (src/vs/workbench/contrib/chat/browser/chatPetService.ts:274). This is needed by agents fix 2.
2. Give agent plugin discovery a `plugins` state that is unresolved (null) until the first refresh, plus a refresh interface (agentPluginServiceImpl.ts:268-289).

### remote-server
1. Model `parseServerConnectionToken`/`determineServerConnectionToken` in `create-server`. Inputs: without-connection-token, connection-token, connection-token-file and user-data-dir. With no args it should generate a mandatory token. The flag conflicts and invalid characters should raise `server-connection-token-parse-error`. A `None` token type should be the only way to disable the gate (src/vs/server/node/serverConnectionToken.ts:50-119).
2. Re-type `extensions-allowed` as an object (id or publisher → boolean | 'stable' | version list, with `'*'` allowing all). `is-allowed` should then look up the id first and the publisher second (allowedExtensionsService.ts:55-100).
3. Add RuntimeExtensionsInput / the Running Extensions editor with Readonly + Singleton + RequiresModal capabilities, so that it opens in the modal editor part (src/vs/workbench/contrib/extensions/common/runtimeExtensionsInput.ts:25).

# UX plan, November 2026: the contract for building `ux-review-2026-11.md`

Read the review first. Build its recommendations, using these decisions.

## Decisions

- **Concept A (Atlas) is the map, Concept B's summary trace is the run view, Concept C's palette ships.**
  Models under 120 components, or with no areas, keep the current compound map.
- **Tabs:** `Overview  Map  Flows  Runs  |  Evidence  History`. `Drafts` isn't built yet, but leave its
  slot. Routes may stay where they are; old URLs keep working.
- **Words:** "Model" in the UI (ontology stays in docs and the CLI). "Schema OK", neutral grey, replaces
  "✓ valid". "World setup (fixture)". "Open decision" for a choice point. "Could reach (static)" for the
  plan. "Race search" for exploration. Use one word, "area", for the top grouping.
- **Trust.** Never let a simulated result read as a fact about the real system:
  - no green for self-checks: green is only for checks against something outside the model;
  - "1805 of 1805 self-checks pass" always carries its caption: consistency, not accuracy;
  - durations say "virtual", and inputs say "generated";
  - a figure says which revision it was measured on, when that isn't the viewed one;
  - no evidence means "Not benchmarked", never silence.
- **One vocabulary for fidelity, in shape and word as well as color:** modeled (solid), partial (half),
  shell (hollow), absent (dashed). `web/src/components/trust/` owns the marks.
- **Evidence comes from `useEvidence` in `web/src/lib/evidence.ts`,** typed in `lib/api/types.ts`:
  `GET /v1/ontologies/{id}/evidence?rev=`, 404 when none is stored. Absent mechanisms have
  `interfaces: []`, so they attach to an area through `area`, as dashed ghost rows.
- **Area** on a component comes from what the sidebar's "by area" already uses. A mechanism's `area` is the
  list's own area, which can differ from a component's: match where they're equal, and fall back to the
  mechanism's interfaces' components when they aren't.
- **Scale rule:** no view draws more than about 40 boxes; it groups and says "and 38 more". No view renders
  rows nobody can see: window anything that can pass about 500 rows.
- Keep what works (review section 2): the citation viewer, the floating run panels, the scrubber, the
  tag hierarchy. Stay neutral: the UI never names a specific customer model.
- Leave room for pillars 2 and 3: views take a `(base, head)` pair where it's cheap, and run compare is
  written as a component that takes any two runs.

## How to verify

- `cd web && npx tsc --noEmit && pnpm lint && pnpm test`, for your paths; ignore a peer's in-progress errors
  and say so.
- Don't restart the shared daemon (7878), the web UI (3000), or touch `~/.mosaic`. For a live look, run your
  own `mosaicd --data-dir $(mktemp -d) --addr 127.0.0.1:<spare>` and load `examples/vllm/vllm.json` or
  `examples/envoy/ontology.yaml`. To run `next dev`, set `NEXT_DIST_DIR`-style isolation only if the repo
  supports it. Otherwise use the fixtures client's tests and leave the live pass to the integrator.
- Never use a broad `pkill`. Kill only pids you started.
- Don't commit. The integrator does, after a real browser pass at all three scales.
